# Inoreader → Obsidian Summary

Inoreaderの有料プランで生成した要約を、MarkdownとしてObsidian Vaultへ保存するChrome拡張です。外部AIへの接続やAPIキーは不要です。要約生成自体はInoreaderの画面で操作します。

## インストール・更新

ZIPを解凍し、Chromeの `chrome://extensions` でデベロッパーモードを有効にします。「パッケージ化されていない拡張機能を読み込む」でmanifest.jsonのあるフォルダを選びます。既存版を更新するときはフォルダのファイルを置き換えて拡張の再読み込みボタンを押してください。旧版のAI設定とAPIキーは新版の編集画面を開いたときに削除されます。

## 使い方

1. Inoreaderで記事を開き、有料プランの要約機能を使って要約を生成します。
2. 要約を表示した状態で拡張アイコンを押します。
3. 記事タイトル、記事の作成日・公開日、元記事へのリンクと要約を確認します。日付が取得できない場合は入力します。
4. 要約を自動取得できない場合は、Inoreaderで要約のテキストだけを選択して、拡張の編集タブで「Inoreaderから再取得」を押します。または要約をコピーして要約欄に貼り付けます。再取得時に要約が見つからない場合、編集済みの要約は保持します。
5. 「Vaultフォルダを選択」でObsidian Vaultのルートフォルダを選び、必要なら保存先を `Clippings/Inoreader` などと指定します。「保存先の設定を保存」で保存先を記憶できます。
6. 「Vaultへ保存」を押します。直接保存では同名ファイルを上書きしません。

選択したテキストを優先して取得するため、記事本文ではなく要約を選択してください。取得した文章が実際の要約と一致しているか保存前に確認してください。

## 保存形式

ファイル名: `261006_記事タイトル.md`（記事の日付が2026年10月6日の場合）

```markdown
---
source: "https://example.com/article"
title: "記事タイトル"
date: 2026-10-06
---

Inoreaderで生成した要約
```

ファイル名の禁止文字は `_` に置き換えます。タイトル部分は120文字までです。要約欄はMarkdownとして保存されます。画面から取得したテキストはプレーンテキストなので、見出しや箇条書きの書式は必要に応じて編集してください。

## 保存方法

Vaultへの直接保存のみです。デスクトップChromeのFile System Access APIを使い、選択したVault内へMarkdownを書き込みます。Obsidianを起動していなくても保存できます。初回にVaultのルートフォルダを選び、書き込みを許可してください。選択先を記憶しますが、Chrome再起動後などは書き込み許可の再確認が必要になる場合があります。

保存先フォルダはVault内の相対パス（例: `Clippings/Inoreader`）で指定します。フォルダは必要に応じて作成します。同名ファイルがある場合は上書きせず、タイトルの変更を求めます。

## データ・制限

記事と要約は編集タブ内に保持され、閉じると失われます。保存先設定はChromeのローカルストレージ、VaultのハンドルはIndexedDBに記憶します。この拡張から外部の要約APIに本文を送信することはありません。

Inoreaderの要約生成ボタンは自動操作しません。Inoreaderの実画面のDOMは未確認のため、要約欄の自動検出は候補セレクターによる補助機能です。表示モードや画面変更で取得できない場合はテキスト選択または貼り付けを使ってください。

## 検証

構文チェックと `node --test core.test.mjs` による日付・Markdown・ファイル名・保存パスの検証を実施しています。ログイン済みInoreaderでの抽出と実Vaultでの保存は未検証です。

実Chromeでは、生成済み要約の選択→拡張で取得→テストVaultへ保存→Obsidianで内容確認を行ってください。同名ファイルの再保存が拒否されることも確認してください。
